# 上传空间、容量与权限

普通上传使用服务器本地磁盘，无需 MinIO。`storage_pool` 保存系统管理员选择的独立空目录；
`upload_space` 保存账号空间、父空间、容量、有效期及启用状态。两个模型已注册到启动迁移。

## 权限与额度

- 系统管理员（级别 3）可查看实际目录、磁盘及分区，创建和启停存储位置，分配或调整空间。
- 普通管理员（级别 2）只能查看自己的虚拟空间，可以向更低级别的用户或游客划分额度。
- 普通用户和游客只能访问分配给自己的空间；游客仍需具有对应页面及接口权限。
- 管理员不能平级分配，不能接管其他管理员的下级空间，不能通过旧令牌保留降级前的权限。
- 上级对下级有额度管理权限，不因此获得读取下级文件内容的权限；系统管理员可检查实际目录。

父空间可用容量 = 总额度 − 自身文件（含未完成上传和版本内容）− 已分配给直属下级的额度。
例如管理员有 100 GiB，自用 10 GiB，分配给两个用户各 20 GiB，则剩余 50 GiB 可自用或继续分配。
下级已使用的数据不重复扣减父空间：父空间在分配时已扣除了下级的完整额度。

调整下级额度时锁定父空间核算；空间不能缩减到自身用量和下级额度之和以下。
子空间有效期不能晚于父空间；访问时逐级检查父空间和账号状态。
到期或停用只冻结访问，保留文件，也不会自动返还已经划分的额度。

## 目录与上传

顶层账号目录为 `<存储根>/users/<账号ID>`，下级目录位于父目录的 `.children/<账号ID>`。
客户端的普通管理员、用户和游客只看到 `/@space` 虚拟路径；请求由服务端按当前账号解析。
目录列表、磁盘概览、文件元数据、同步结果和 WebSocket 消息均隐藏真实服务器路径。

`.children`、`.uploads`、`.versions` 为服务内部目录，不对普通文件浏览、直接下载或目录打包开放。
路径访问拒绝越界、同名前缀目录、Windows 备用数据流、符号链接和目录联接。
没有分配空间的普通账号不会回退到全局磁盘白名单。

分片临时文件放在账号的 `.uploads` 内，预分配大小直接计入容量，通过账号锁和数据库行锁避免并发超额。
合并是同空间内重命名，不重复计算。超过上传会话期限的临时文件由清理器处理；空间到期不删除正式文件。
版本内容放在账号的 `.versions` 内，也计入用量；空间不足时保留版本元数据但不额外留存内容，日志会说明原因。
快传继续沿用原有独立目录、配额和分享有效期。

同步目录保存、文件变更、扫描、收编及镜像回写复用相同路径权限。旧目录不会自动搬迁：
普通账号需先分配空间，再把同步的远端路径设为自己的空间或其中的子目录。

## 文件概览与默认目录

文件管理概览将 `/@space` 显示为“我的文件空间”，容量直接按字节计算，后端同时提供容量文本和百分比。
目录页支持新建文件夹、点击名称或整行进入目录、返回上级及浏览历史导航；读取失败会显示原因，快速切换时旧响应不会覆盖当前目录。
新建文件夹使用 `POST /file/create-directory`，只接受单个目录名，复用空间归属、有效期与容量锁校验；已有文件或目录不会被覆盖。
访客只有获得上传页面权限时才能新建文件夹，单独的浏览权限不能执行该写操作。
文件点击先在应用内预览；不支持预览的类型显示说明，由用户主动下载。
桌面下载先选择保存位置，再由 Rust 流式写入并进入现有传输列表；同名本地文件不覆盖，错误响应和未完成的下载不会被保留为成功文件。
新增原生命令需要重新编译桌面 Rust 部分，单独的 Vite 热更新无法加载该命令。
分配空间时创建“我的文件”目录；已有可用空间读取时补齐，保留原有内容，不搬迁已有文件。
上传页默认使用服务端的 `default_path`，该字段同样经过虚拟路径转换。
根目录不存在时返回错误，不通过初始化默认文件夹自动重建根目录。

## 账号删除与空间清理

用户管理的“删除账号和空间”和访客删除共用账号清理服务。不能删除自己或平级、上级账号；
普通管理员只能删除自己创建的未分配账号，或从自己空间分配的下级账号。
存在下级账号或下级空间时拒绝删除，须从下级逐一处理，避免递归误删其他账号的数据。

先将账号 `status` 持久设为 `-1` 并禁用其空间、断开连接；旧令牌和缓存分享立即失效。
清除隔离空间、上传临时文件、版本文件、分享副本及快传内容，再删除账号和关联记录，保留审计日志。
历史同步的外部目录和客户端文件不在服务端隔离空间的清理范围内。
系统管理员代空间创建的分享也会撤销，避免留下独立分享副本。

清理失败时响应 `data.cleanup_pending=true`，账号保持不可登录的“清理中”状态，空间行及父空间占用额度保留。
管理列表可刷新查看状态并手动重试；后台启动即扫描，每分钟重试，成功后才物理删除账号和空间分配、返还额度。
该状态复用现有账号状态字段，不增加依赖内存的临时任务；删除中的账号不可重新启用或分配空间。

## PC 页面与公共响应

“上传管理”包含本人用量、有效期、待上传队列和传输进度，桌面端复用现有传输事件及暂停、继续、取消能力。
`UploadSpaceStatus.vue` 在上传页和下级分配页共用；`UploadSpaceAdmin.vue` 供系统管理员和普通管理员共用。
磁盘选择和实际目录配置只在系统管理员视图中出现。

`pkg/response` 使用 `Envelope` 和 `PageData` 固定 JSON 结构，提供成功、失败、分页及流式错误封装。
文件、管理、同步接口已接入，系统磁盘监控响应也经过路径转换。
约束测试禁止文件和管理接口重新手写 `c.JSON(...gin.H{"code":...})`。
文件下载和缩略图的失败使用真实 HTTP 状态码；业务接口继续兼容 HTTP 200 加业务码的客户端约定。

菜单路由元数据接口中的 `path` 是客户端 URL，明确排除文件路径脱敏；普通账号的文件、空间、同步路径仍按原规则处理。
路由菜单直接查数据库，不通过 Redis。客户端刷新同时核对版本、权限级别和路由内容，防止同版本的异常菜单响应持续留在内存或缓存中。

## 应用与验证边界

本次不自动修改已有账号的文件位置、数据库连接配置，也不自动发布或重启服务。
开发服务应先确认连接 `syncfile-dev`，再通过启动迁移建表，由系统管理员建立存储位置并分配额度。
管理页面复用现有“上传管理”路由，无需静默新增或恢复服务器路由目录中的条目。

应用不再公开挂载 `/temp`，分享下载统一经过有效期与源空间校验。
部署时还需确认反向代理没有公开暴露上传根目录或分享临时目录；Nginx 加速位置必须为 `internal`。
